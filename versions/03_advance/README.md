# Neovim 설정

## 에디터 설정

`:Settings` → `Editor settings` 또는 `:SettingsEditor`에서 항목을 선택하면
설정이 바뀌고 `stdpath("state")/ui-toggle-settings.json`에 기존 미니맵·스크롤뷰
토글과 함께 저장된다. 재시작 시 복원되며, 열린 일반 파일 창과 이후 여는 창에 적용된다.
터미널, 도움말, 파일 트리, 프롬프트, 플로팅 창과 미리보기 창은 적용 대상에서 제외한다.

| 항목 | 동작 / 기본값 |
| --- | --- |
| Auto pairing | 괄호·따옴표 자동 닫기, 켜짐 (`nvim-autopairs`) |
| Line numbers | absolute → relative → hybrid → off 순환, 기본 absolute |
| Wrap long lines | 긴 줄을 화면에서 줄바꿈, 켜짐 (파일 내용은 변경하지 않음) |
| Wrap at word boundaries | 단어 경계에서 화면 줄바꿈, 꺼짐; wrap이 켜져야 효과 있음 |
| Indent wrapped lines | 화면에서 이어지는 줄의 들여쓰기 유지, 꺼짐; wrap이 켜져야 효과 있음 |
| Highlight cursor line / column | 현재 줄 / 열 강조, 각각 꺼짐 |
| Show whitespace | 기존 탭·앞뒤 공백 표시, 켜짐 |
| Spell checking | `spelllang`에 따른 맞춤법 표시, 꺼짐 (기본 영어) |

relative는 커서 줄을 0으로 표시하고 다른 줄은 커서까지의 거리로 표시한다.
hybrid는 커서 줄만 실제 줄번호, 나머지는 상대 번호로 표시한다.
오토페어링 토글은 플러그인의 활성 상태를 제어하며, 기존 `Ctrl+l` 이동 키는 유지된다.
나머지 항목은 추가 플러그인이 필요 없는 네오빔 기본 옵션이다.
들여쓰기 폭과 탭/공백 규칙은 기존 파일 형식별 설정을 사용한다.

참고: [네오빔 옵션 문서](https://neovim.io/doc/user/options/),
[Snacks 토글 사례](https://github.com/folke/snacks.nvim/blob/main/docs/toggle.md),
[nvim-autopairs 활성화 API](https://github.com/windwp/nvim-autopairs#plugin-integration).

## `markdown-preview.nvim` 새로고침 패치

- 미리보기 URL이 `/page/{bufnr}`에서 `/{bufnr}`로 바뀐 뒤 새로고침하면
  404 또는 `/NaN`이 되는 문제를 막기 위해, 짧은 주소를 `/page/{bufnr}`로
  임시 리다이렉트한다.
- `lua/config/markdown_preview.lua`가 시작 시와 플러그인 빌드 후 설치된
  `app/routes.js`에 패치를 적용한다. 이미 적용된 패치는 중복 삽입하지 않는다.
- 실행 중인 미리보기 서버에는 재시작 후 반영된다.
- 마지막 미리보기 탭의 연결이 끊긴 후 10초 동안 재연결이 없으면 서버도
  종료한다. 새로고침으로 재연결되면 종료 예약을 취소하며, 다른 미리보기 탭이
  연결되어 있으면 서버를 유지한다. 이 패치도 시작 시와 빌드 후 `app/server.js`에 적용한다.

### 창별 파일 버퍼 윈바

일반 편집 창 상단에 해당 창에서 열었던 파일을 표시합니다. 파일명을 클릭하면
그 창에서 전환하고, `×`를 클릭하면 그 창의 목록에서 제거합니다. `+n`(초록)·`-n`(빨강)은 마지막 저장 이후 추가·삭제한 줄 수이며, `‹` / `›`로 긴 목록을 이동할 수 있습니다.

다른 창의 목록에 남아 있는 버퍼는 숨김 상태로 유지하고 마지막 항목을 닫을 때
삭제합니다. 마지막 참조에 저장하지 않은 변경이 있으면 닫기를 막습니다.
기존 현재 버퍼 닫기 키도 윈바가 켜져 있을 때 이 규칙을 따릅니다.

`Settings → Editor settings → Window buffer bar`에서 표시를 전환합니다.
하위 `Compress buffer names`(기본 꺼짐)를 켜면 이름을 점진적으로 `...`까지
줄여 전체 목록을 표시하고, 최소 너비로도 넘칠 때만 화살표를 표시합니다.
화살표는 해당 방향에 숨겨진 항목이 있을 때만 나타납니다.
마지막 항목의 ×와 Space q/Q는 분할 창을 닫으며, 마지막 창에서는 대시보드로 돌아갑니다.
설정의 `ㄴ` 항목은 바로 위 상위 옵션에 종속되며, 상위 옵션을 끄면 흐리게 표시되고 선택할 수 없습니다.
끄면 창별 참조 보호도 해제되어 기존 버퍼 닫기·자동 닫기 동작으로 돌아갑니다.
세션에는 창별 목록 순서와 현재 항목이 저장됩니다. 일반 파일은 디스크에서 다시
읽으며, 이름 없는 버퍼는 내용을 함께 저장합니다. 기존 세션도 불러올 수 있습니다.

검증 스크립트: `tests/winbar.lua`(버퍼 수명·설정·세션),
`tests/winbar_ui.lua`(실제 임베디드 UI 마우스 입력).
테스트는 별도의 `XDG_STATE_HOME`을 지정하고 `nvim --headless -u NONE -i NONE -l`
뒤에 스크립트 경로를 전달해 실행합니다.

윈바의 현재 항목은 편집 창 본문과 같은 배경색으로 이어지고, 비선택 항목은 별도 박스로
구분합니다. 파일명 앞에는 파일 유형 아이콘을 표시합니다. 테마 변경 시 색상이 갱신됩니다. 터미널도 `Terminal 번호`로 표시하며,
다른 창에서 참조 중이면 실행을 유지합니다. 실행 중인 마지막 터미널 항목을 닫으면
종료 여부를 확인합니다. 터미널 세션 복원은 저장한 작업 디렉터리에서 새 셸을
시작하는 방식이며, 이전 프로세스나 출력 내용까지 복구하지는 않습니다.

일반 모드에서 `<leader>bh` / `<leader>bl` 또는 `<leader>b<Left>` / `<leader>b<Right>`는
현재 창 윈바의 이전/다음 버퍼를 엽니다. `<leader>bH` / `<leader>bL`은 현재 항목의 순서를
왼쪽/오른쪽으로 한 칸 옮깁니다. 열린 버퍼·커서 위치는 그대로이며, 목록 끝에서는 이동하지 않습니다.
순서는 세션에 저장되고 윈바가 꺼져 있으면 단축키도 동작하지 않습니다.

윈바의 파일명이나 터미널 이름을 드래그하면 같은 윈바 안에서 순서를 바꾸거나,
다른 일반 창의 윈바/본문에 놓아 해당 창으로 전달할 수 있습니다. 전달할 때 원래
창의 항목만 제거하고 버퍼는 삭제하지 않습니다. 파일 트리에서는 파일 항목을
끌어 원하는 일반 창에 놓으면 그 창에서 열립니다. 디렉터리 드래그는 지원하지 않습니다.
일반 창 우클릭 메뉴의 `Split Vertical` / `Split Horizontal`은 빈 창을 분할합니다.

파일 트리 우클릭에는 전용 메뉴(새 파일/폴더, 이름 변경, 파일 복사·잘라내기·붙여넣기·삭제,
파일명/경로 복사)를 표시합니다. 새 폴더는 생성 입력 끝에 `/`를 붙입니다. 맨 아래의
Split Vertical / Split Horizontal은 우클릭한 파일을 새 편집 창에 엽니다.
설정 목록은 유형과 사용 빈도 순서로 정리하며, 내림차순에서 낮은 중요도 항목을 앞 인덱스에 둡니다.

### 플로팅 윈바

윈바를 켜면 플로팅 슬롯과 각 분할에도 개별 버퍼 목록을 표시합니다.
재할당한 이전 버퍼는 목록에 남고, Space bh/bl 및 좌우 방향키로 전환,
Space bH/bL로 순서 변경, 마우스로 선택·닫기·드래그할 수 있습니다.
Space q/Q와 ×는 현재 항목을 닫고, 마지막 항목이면 해당 플로팅 분할을 닫습니다.
숨긴 플로팅 슬롯의 목록도 버퍼 참조로 보호되며, 슬롯 재표시와 세션 복원 시
목록 순서와 선택 버퍼를 유지합니다. Space bb에서 숨긴 항목의 플로팅 소속도 표시합니다.
윈바를 끄면 기존 플로팅 버퍼 처리 방식을 사용합니다.
